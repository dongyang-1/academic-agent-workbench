# 稳健性检验路由器 (Robustness Router)

## 一、 这个 Skill 是干什么的
`robustness-router` 负责根据基准模型的因果识别设计（DID / IV / RDD / SCM），自动路由并组装该识别设计专属的**稳健性检验矩阵**。它杜绝“机械罗列所有检验”，而是精准调用 L3 组件（如安慰剂检验、聚类层级调整、替代规格、异质性与机制分析）。

## 二、 什么时候使用
- 基准回归完成且估计系数显著后；
- 需要评估基准结论在不同设定下的稳定性时。

## 三、 什么时候不要使用
- 当基准估计系数本身在统计与经济上都不显著，且识别设计存在致命缺陷时。

## 五、 检验组合映射逻辑 (由设计驱动)
根据 `identification-strategy` 选定的设计自动构建针对性矩阵：

```text
 ┌──────────────────────┬────────────────────────────────────────────────────────┐
 │ 识别策略 (Strategy)  │ 专属稳健性检验组合 (Robustness Pipeline)              │
 ├──────────────────────┼────────────────────────────────────────────────────────┤
 │ DID / Staggered DID  │ 1. 平行趋势动态检验 (Event Study)                     │
 │                      │ 2. 处理时间/个体随机化安慰剂检验 (placebo)             │
 │                      │ 3. 剔除特殊样本/缩尾敏感性 (alternative-sample)        │
 │                      │ 4. 考虑预前期趋势的 HonestDiD 边界 (sensitivity-bounds)│
 ├──────────────────────┼────────────────────────────────────────────────────────┤
 │ IV (工具变量)        │ 1. 弱工具变量 Effective F 与 AR 置信区间诊断 (iv)       │
 │                      │ 2. 异方差/自相关下 Wild Cluster Bootstrap (clustering) │
 │                      │ 3. 排除其他解释变量与替代工具变量检验                  │
 ├──────────────────────┼────────────────────────────────────────────────────────┤
 │ RDD (断点回归)       │ 1. 带宽敏感性测试与多项式阶数检验                      │
 │                      │ 2. 伪 Cutoff 断点安慰剂检验 (placebo)                  │
 │                      │ 3. 协变量连续性检验 (Covariate Continuity)             │
 └──────────────────────┴────────────────────────────────────────────────────────┘
```

## 六、 方法选择逻辑
- **设计驱动**：只有符合特定识别假定的检验才会触发（如对 RDD 跑平行趋势是无意义的）；
- **主次分明**：区分核心稳健性检验（必须通过）与辅助稳健性检验。

## 七、 诊断要求
- 汇总各稳健性检验的系数方向、显著性与符号一致性；
- 检查是否存在特定子样本下结果翻转的情况。

## 八、 输出结果
- 稳健性检验矩阵汇总表；
- 各 L3 组件生成的回归与图表对象。

## 九、 失败条件
- 多数核心稳健性检验出现系数符号翻转或显著性完全丧失。

## 十、 底层工具
- AER 稳健性菜单标准；
- Python / Stata 稳健性组合管道。

## 十二、 中文用户说明与防避坑指南
顶刊论文的稳健性检验不是多多益善，而是“打中要害”。`robustness-router` 会针对所用因果设计的脆弱点（如 DID 的平行趋势、IV 的弱工具）精准打补丁，极大提升结果的说服力。
